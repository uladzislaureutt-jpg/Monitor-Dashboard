# W-Review: сбой подготовки карточек 18 октября, 20:44–20:48 Минск

В журнале: Gemini structured requests HTTP 400 INVALID_ARGUMENT, затем HTTP 200 в JSON-режиме, но missing_card. Cloudflare/Groq также отвечали 200; часть карточек не проходила минимальное подтверждённое покрытие. Сообщение providers_unavailable не различало транспортную ошибку и отказ валидатора.

Исправлена регрессия v114: responseFormat.text.mimeType должен быть enum APPLICATION_JSON (GenerateContent REST), а не строка application/json от responseMimeType. Резерв использует responseMimeType + responseJsonSchema с нормализованными типами вместо отвергаемого responseSchema. JSON-only режим сохранён.

В текстовый контракт добавлены точная оболочка cards и пример полей; рядом с каждым материалом явный CARD_INDEX (0/1), чтобы исключить неоднозначность с MATERIAL_1/2. Это профилактика нарушения формы; по прежним логам нельзя установить точную форму отклонённого ответа. Добавлена безопасная диагностика: наличие cards-массива, число карточек и числовые индексы без содержимого статей. Уровень проверки фактов не ослаблен, автоматического переименования/перестановки чужих карточек нет.

Сохранены единый итоговый синтез v115 и прежние карточки. Нового установщика не требуется. Локальные проверки не заменяют следующий рабочий запрос с реальными провайдерами.
