# W-Review 0.8.67

Подготовка пула сохраняет основной маршрут Gemini 3.5 Flash-Lite. Запросы
используют JSON Schema; при несовместимости формата меняется формат на той же
модели (legacy schema, затем JSON MIME), а не качество модели. Голый текстовый
режим не используется для Evidence и карты. Обрезанный ответ не чинится выдуманным
окончанием. Пригодная карточка сохраняется, неудачная статья повторяется отдельно.

Подготовка ограничена общим временем 130 секунд на запрос. Повтор временной
ошибки ограничен одной попыткой; минутный 429 учитывает короткий Retry-After,
суточный лимит не повторяется. После основного маршрута резерв качества —
Cloudflare GPT-OSS-120B, затем аварийные Gemini 3.1 Flash-Lite / Groq 20B.
Уже принятые полноценные карточки не заменяются резервом ради единообразия модели.

Для статей от 4500 знаков менее восьми записей или отсутствие покрытия одной
из трёх частей текста — сигнал для адресного повтора. Это не смысловая проверка
и не требование придумать факты. Если более полный результат получить нельзя,
пригодная карточка сохраняется с предупреждением. Модель и предупреждения
сохраняются отдельно для каждой статьи.

При неизменном SHA-256 исходника клиент сохраняет прежний разбор, если новый
теряет не менее трёх записей и более 20% их количества либо не менее трёх
покрытых фрагментов и более 25% покрытия. Новый вариант остаётся доступен в
карточке через «Использовать новый разбор». Это сигнал регрессии, не утверждение,
что многословный результат всегда точнее. При изменении исходника сравнение
не блокирует новую карточку.

Карта больше не превращает пропущенные источники в выключенные дополнительные
темы с низким приоритетом. Неполный план отправляется на ограниченное исправление
той же моделью; при неудаче используется резерв или возвращается понятная ошибка.
Действительно периферийные темы, выделенные моделью с объяснением, остаются
доступными для выбора оператора. Из общего промпта убраны номера и сюжеты одного
конкретного пула. Существующие карточки и профиль стиля сохраняются; для нового
контракта достаточно пересчитать тенденции, переанализ пула остаётся явным действием.

Финальный обзор по-прежнему создаётся одним проходом GPT-OSS-120B. Автоматическое
дописывание, отдельный аудит обзора и дополнительные классификаторы не добавлены.

Проверка: поведенческие тесты подготовки с моделируемыми ошибками 400, 429,
MAX_TOKENS, неполными пакетами и дедлайнами; регрессия карточек и полнота карты;
проверка типов frontend и серверных модулей; production-сборка frontend.
Частота реальных переключений и качество текста проверяются новым прогоном
одного и того же пула. Локальные тесты не подменяют сравнение моделей на материалах.
