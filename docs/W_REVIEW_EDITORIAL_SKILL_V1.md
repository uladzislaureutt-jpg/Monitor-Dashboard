# W-Review — редакционный навык и контракт v1.0 (проект)

**Статус:** контракт подготовлен для внедрения и испытаний. **Не активирован** в production `w-review-ai`; документация не меняет поведение установленного приложения.

## Назначение

Получать из утверждённого оператором пула до 18 материалов **единый аналитический обзор медиаполя** в индивидуальной авторской манере, заданного объёма с пробелами, затем экспортировать текущий мастер-текст в DOCX. Не подменять обзор тенденций последовательным пересказом отдельных статей.

## Входной пакет

1. Тема, задачи и исключения оператора, выбранные смысловые тенденции, параметры плотности цитат/заголовков/экспертов, `target_chars` (1000–8000).
2. Полный список `P01...P18`, с названием источника, исходным заголовком, URL и редакционным текстом (до 10 000 знаков на материал).
3. **Структурированные Evidence Cards**. Помимо фактов/имен/дат, обязательно: кто является субъектом оценки, собственная позиция редакции или нейтральный пересказ, подлинные заголовки, конкретный говорящий для каждой цитаты, точный русский перевод, особенности ракурса издания, уникальные аргументы/эксперты и ограничения достоверности.
4. Утверждённая оператором карта смысловых тенденций с привязкой независимых карточек к каждому сюжету. Не делить материалы по очереди СМИ или по простому признаку страны.
5. Постоянный пакет авторской манеры: `STYLE_PROFILE` + 2–4 фрагмента из наиболее близких оригинальных редакционных образцов. Помечать фрагменты как `STYLE_ONLY`: их факты и цитаты запрещено переносить в текущий обзор.

## Основной редакционный контракт

- Сначала понять смысловые акценты и противоречия медиаполя, затем соединить относящуюся к ним подтверждённую фактуру из разных публикаций в связный текст. Не выдавать карточки за порядок абзацев.
- Каждая оценка имеет своего говорящего: журналистский пересказ, редакционная позиция, цитируемый политик/эксперт и газетный заголовок — **разные категории**. Нельзя переносить негативную западную оценку на российские издания или превращать нейтральное сообщение в поддержку.
- Обобщения **обязательны**, но национальная или региональная редакционная тенденция требует независимых подтверждений соответствующих публикаций. Разные реакции не превращать в искусственный консенсус; расхождения часто представляют важнейший аналитический сюжет.
- Внимательно использовать **весь информативный пул**, включая содержательные публикации менее известных СМИ. Не перечислять все названия только для статистики и не считать агентские перепечатки независимыми редакционными мнениями.
- Использовать факты, числа, имена, экспертные комментарии, переводы и цитаты только из текущих Evidence Cards, а не из знаний модели или старых стилевых образцов.
- Полностью соблюдать индивидуальную манеру: зачин, цитатно-аналитическое развитие, ритм абзацев, переходы, характер выводов. Не навязывать одинаковые объёмы тенденциям или фиксированное число абзацев.
- Не завершать искусственными формулами «Таким образом», «В заключение». Допускать органичные авторские обобщения с подтверждённой смысловой опорой.
- Писать видимый текст по-русски (если оператор не указал другой язык); иностранные цитаты/заголовки переводить, собственные названия СМИ сохранять; использовать «ёлочки», тире –.
- Цель — `target_chars` знаков **с пробелами в поле `review_text`**, отклонение ±5%. Не заполнять недостающую длину повторами или выдумками. Для 8000 целевой коридор 7600–8400. Отказ от рефератной композиции важнее принудительных квот абзацев.

## Исполнение

1. `evidence_batch`: один пакет материалов → одна идентифицированная карточка на статью. Сохранять автора цитат и тональность источника явно; при сомнениях писать `unestablished`, не придумывать позицию редакции.
2. `editorial_map`: смысловые тенденции из карт, оператор утверждает/исправляет.
3. `style_profile`: один раз создавать профиль и набор реальных связных фрагментов образцов, без дополнительных действий оператора.
4. `synthesize`: **один** запрос GPT-OSS-120B по всему комплекту. Технический резерв: Cloudflare №1 → независимый Cloudflare №2 → Groq GPT-OSS-120B. Не делать скрытых циклов «генерация—аудит—дописать—повторить».
5. Показать готовый редактируемый текст вместе с числовым индикатором `факт / цель`. Программно считать символы, а не полагаться на самопроверку модели. Сохранить текст и при выходе за ±5%, не запускать скрытых повторов.
6. `export_w_review_docx`: экспортировать единственный мастер-текст **после** исправлений оператора и без дополнительного обращения к ИИ. Формат W-Review задаётся постоянно в самом экспортёре, как в SEP-Monitor: А4, Arial 16 пт, текст по ширине, красная строка, шрифт/курсив названий СМИ и предусмотренные акценты; достоверные ссылки только на конкретные публикации. Оператор **не выбирает и не загружает Word-шаблон при экспорте**. При разовой калибровке внутреннего W-Review пресета допустимо использовать оригинальный Word-эталон.

## Оригинальные образцы (предметы оформления, а не фактические источники)

`ШОС_Бишкек.doc`, `Саммит_ЕАЭС_Астана.doc`, `Трамп в Пекине_Путин_едет.doc`, `Путин_Трамп_недельный.doc`, `Россия_экономика_война.doc`, `Искусственный интеллект.doc`, `Казахстан_Армения.doc`, `Украина_Азербайджан.doc`, `Украина_Азербайджан_Трамп.doc`. Неполный `Украина война_апрель.doc` не использовать как самостоятельный стилевой образец.

## Совместимость, ограничения и приёмка

Не изменять три тематических рабочих пространства, общий профиль стиля и правило **двух успешных генераций по теме за сутки для оператора (администратор без ограничений)**. Не делать обязательных ИИ-проверок после ручных правок.

**Принципиальное ограничение:** ни `max_tokens`, ни формулировка ±5% не гарантируют математически точную длину текста при единственном обращении к GPT-OSS-120B. Production уже возвращал `finish_reason=stop` примерно на 5 тыс. знаков при цели 8 тыс. Не имитировать выполнение допуска, если результат короткий. Замерять и сравнивать фактический объём.

Детальная версия навыка включает `SKILL.md`, источниковую схему, правила стилевых фрагментов, шаблон одного запроса, требования к DOCX и проверочные случаи. Перед внедрением необходимо отдельно испытать её на сохранённом реальном пуле из 18 публикаций и сопоставить качество с исходными Word-эталонами.

**Текущие пробелы в коде, требующие внедрения:** `evidence_batch` не фиксирует автора/полярность оценки структурированно; `wSynthesize` передаёт только текстовый `style_profile`, а не выбранные фрагменты образцов; `export_w_review_docx` не получает URL каждой публикации и создаёт DOCX без копирования исходного Word-шаблона. Поэтому сам по себе этот файл НЕ активирует контракт.
