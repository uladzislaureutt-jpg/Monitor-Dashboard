## Currents: свободный лимит есть, но сегодняшние страницы не обрезаны

Рабочие пределы: 64 запроса/сбор, 120/сутки, 3 600/30 дней, резерв 25. Сервис после сбора показывал 164 из 250, значит за его сутки израсходовано 86, включая более ранние проверки. Ни разовый, ни суточный ограничитель помощника в №3 не был достигнут.

Из 31 включённого языкового направления и дополнительных написаний результат дали только английский (12), немецкий (3), испанский (2) и чешский (3). Все ответы короче 20 результатов; второй страницы не возникло. Поэтому простое увеличение числа страниц или повтор тех же запросов с фильтром страны не решает наблюдаемую проблему. Дополнительный фильтр сужает поиск и полезен прежде всего для контроля насыщенной выдачи, а не как гарантия расширения пустой.

Выявленные ограничения реализации:

1. Альтернативное написание обычно проверяется только при пустой первой странице. Поэтому `Lukashenka` пропускается, если `Lukashenko` уже что-то нашёл; аналогично вторые варианты немецкого/испанского/чешского направлений.
2. Польский список содержит `Łukaszenka`, `Lukaszenka`, `Lukaszenko`, но не `Łukaszenko`, хотя последний уже распознаётся общим фильтром. В арабском запросе можно дополнительно проверить `لوكاشنكو` рядом с текущим `لوكاشينكو`. Это кандидаты для ограниченной проверки, а не доказанная прибавка статей.
3. Все запросы жёстко задают `type=1` (news). API отдельно поддерживает `type=2` (articles). Проверка второго класса может добавить материалы и аналитику, которые текущий класс исключает; реальная прибавка требует проверки на этом ключе. Класс discussion не нужен для каталога СМИ.

Предлагаемый следующий шаг: самостоятельная проверка значимых вариантов даже после непустого ответа, затем ограниченный проход `type=2` по английскому, немецкому, польскому, французскому, итальянскому, испанскому, турецкому, украинскому и чешскому языкам; расширять по подтверждённому результату. Сохранять исходное окно и общий отбор по каталогу/релевантности. Отдельно измерять новые принятые карточки, полезные дополнения текста и повторы. Пустые направления переводить в менее частую ротацию только по нескольким дням наблюдений, не по одному нулю.

## The News API: есть конкретный непросмотренный остаток

Рабочие пределы: 40 запросов/сбор, 80/сутки, 2 400/30 дней, резерв 10. Ключ возвращает до 3 статей за страницу. После сбора остаток 42 из 100: за сутки потрачено 58, из них 30 в №3. Разовый предел 40 не достигнут.

Выполнено 27 начальных запросов к группам по 40 доменов и 3 перехода на вторую страницу. По метаданным этих групп найдено 32 совпадения, извлечено 22. В группе №20 (21 источник RU, 18 RS, 1 SA) сервис сообщил о 16 совпадениях, просмотрены первые 6. Третья страница не была создана: после второй страницы реализация требует новых/ещё необработанных кандидатов. Дополнительно текущий предел направления — 3 страницы, его также недостаточно для 16 результатов при размере страницы 3.

Для просмотра оставшихся 10 совпадений потребовалось бы ещё 4 запроса (страницы 3–6), если набор результатов остаётся тем же. Это укладывалось даже в действующий разовый бюджет: 30 → 34. Непросмотренные совпадения не следует считать десятью новыми карточками: среди них могут быть повторы и нерелевантные публикации.

Предлагаемые изменения:

1. Продолжать небольшую известную выдачу до исчерпания `meta.found`/неполной страницы в пределах бюджета, даже если первые страницы уже известны. Допустить до 6–8 страниц на такое направление.
2. Делить только насыщенные группы на меньшие группы по 5–10 доменов, преимущественно одной страны. При лимите 3 статьи общая группа из 40 изданий может отдавать страницы одного активного издателя и затруднять просмотр остальных. Не дробить сразу весь каталог: это даст слишком много пустых запросов.
3. Для очень больших групп приоритетно проверять более слабые страны и издания, а большой поток RU/UA учитывать отдельно. При необходимости разделять исходное окно на интервалы, сохраняя те же границы дат.

## Бюджеты для расширенного механизма — предложение, пока не применено

| Сервис | На сбор | В сутки | За 30 дней | Резерв |
|---|---:|---:|---:|---:|
| Currents | до 120 запросов | до 200 | 6 000 | 25 |
| The News API | до 70 запросов | до 90 | 2 700 | 10 |

Повышать эти потолки имеет смысл вместе с появлением дополнительных направлений/страниц. Сейчас простое повышение не изменит выполненные 56 и 30 запросов: очередь закончилась раньше лимитов. План расхода адаптивный — в обычный день ожидается меньше, при насыщенной выдаче доступен запас. Оба бюджета остаются ниже квот аккаунтов с учётом резерва. Окно 26 часов, тематическая строгость и общий каталог не расширяются автоматически ради расходования остатков.

Порядок внедрения: сначала пагинация The News API и локальные варианты Currents, затем проверка класса articles и адаптивного распределения по странам. Рост числа запросов оценивать по добавленным публикациям после общего индекса, а не по сырому числу ответов.
