# Monitor — 0.5 Network Workroom

Windows x64 desktop-приложение для накопления, поиска и анализа пакетов Dashboard Data Contract SEP-Monitor с небольшой общей рабочей комнатой для 5–7 пользователей.

## 0.5

- «Рабочая комната» стала сетевой;
- авторизация — отдельные email/password аккаунты Supabase Auth;
- сообщения защищены Postgres RLS;
- заметки и объявления общие для всех подключённых пользователей;
- объявления закрепляются вверху;
- на кнопке в левой панели показываются непрочитанные;
- новые сообщения проверяются примерно раз в 20 секунд;
- при отсутствии сети остаётся локальный кэш последней ленты;
- у каждой публикации появилась кнопка **«Обсудить / Абмеркаваць»**;
- в комнату при этом передаются только заголовок и URL, сам архив мониторинга остаётся локальным;
- старые локальные заметки 0.4.x не уничтожаются и могут быть опубликованы по одной;
- интерфейс комнаты полностью RU/BE;
- подписи географического treemap очищены от белой тени: на светлой заливке используется тёмный текст без тени, на насыщенной — светлый текст с мягкой тёмной тенью.

## Backend

Шаблон backend находится в:

`backend/supabase/workroom.sql`

Пошаговая настройка:

`docs/WORKROOM_SETUP_0.5.md`

Для приложения нужны только Project URL и **Publishable / anon key**. `service_role` key нельзя хранить в desktop-приложении.

## Что остаётся локальным

- SQLite мониторинга;
- архив публикаций;
- выдержки материалов;
- аналитика;
- dashboard-bundle;
- GitHub Auto Sync settings.

Backend рабочей комнаты получает только сообщения, метаданные автора и при явном действии «Обсудить» заголовок + URL публикации.

## Auto Sync

Механизм GitHub Actions Auto Sync из 0.4.x сохранён. Он не зависит от Supabase: если рабочая комната не настроена, Dashboard/Archive/Analytics/Auto Sync продолжают работать.

## База данных

Схема локальной SQLite мониторинга в 0.5 не меняется. Существующая база и импортированные run сохраняются.

## Сборка

Используйте существующий workflow `Build Monitor Dashboard Windows x64`.
