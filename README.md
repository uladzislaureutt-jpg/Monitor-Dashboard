# Monitor — 0.5.3

Windows x64 desktop-приложение SEP-Monitor: локальный архив SQLite, поиск, аналитика, GitHub Auto Sync и общая сетевая «Рабочая комната».

## Узкий пакет 0.5.3 — Relevance Moderation

Этот релиз добавляет общий для 5–7 пользователей слой редакционной модерации уже собранных публикаций.

- любой авторизованный пользователь может поставить возле публикации **красный флажок** «нерелевантно?»;
- при наведении показываются имена всех пользователей, поставивших флажок;
- пока есть хотя бы один активный флажок, публикация **остаётся видимой в Архиве и ленте «Последние материалы»**, но **не участвует в KPI, статистике и диаграммах**;
- пользователь может снять собственный флажок;
- администратор может нажать **«Оставить»**, снять все флажки и вернуть публикацию в аналитику;
- администратор может нажать **«Удалить»** — создаётся общий durable tombstone: публикация скрывается из Архива и ленты у всех пользователей и не возвращается после Auto Sync;
- физически исходный bundle и документ в SQLite не уничтожаются: это защищает от повторного появления материала при синхронизации и сохраняет воспроизводимость данных;
- состояние флажков и исключений синхронизируется через уже настроенный Supabase Workroom; локальная SQLite хранит его снимок для аналитики и офлайн-режима.

## Маркер официальной реакции

В карточках Архива, поиска и «Последних материалов» теперь выводится метка **«реакция зафиксирована»** / **«рэакцыя зафіксавана»**, если `official_response=true`.

Метка означает только наличие зафиксированного официального комментария/ответа; она **не означает, что проблема решена**.

## Совместимость

- обновление устанавливается **поверх 0.5.2**;
- SQLite автоматически обновляется со schema 3 до **schema 4**;
- существующие runs, Auto Sync, Workroom, RU/BE, preview images и аналитика сохраняются;
- `.github/workflows` не меняются;
- текущий живой проект Supabase `monitor-workroom` уже обновлён серверной схемой 0.5.3; повторно выполнять SQL для него не нужно.
