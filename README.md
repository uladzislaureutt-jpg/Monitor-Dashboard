# Monitor — 0.5.1

Windows x64 desktop-приложение SEP-Monitor: локальный архив SQLite, поиск, аналитика, GitHub Auto Sync и общая сетевая «Рабочая комната».

## Что нового

- полная RU/BE локализация не только оболочки, но и известных рубрикаторов SEP-Monitor: темы, регионы, типы/статусы источников и подписи/подсказки диаграмм;
- исходные заголовки, выдержки и названия СМИ не переводятся;
- KPI `официальный ответ` переименован в `зафиксированная реакция` с пояснением: это наличие официального комментария/ответа, а не признак решения проблемы;
- «Динамика публикаций»: столбцы + средняя, линия + 3-точечное скользящее среднее, линии четырёх ведущих проблемных тем;
- четвёртый аналитический блок «Персоналии и понятия»;
- понятия строятся по `event_object` с fallback на подкатегорию;
- персоналии выделяются консервативной эвристикой из заголовков и выдержек; это промежуточный слой до полноценного `entities.jsonl`;
- поддержка `preview_image_url` и скрываемая фотолента; она появляется только когда будущие bundle содержат публичные preview-image;
- Workroom 0.5.1: новый пользователь при первом входе сам задаёт отображаемое имя и позже может его изменить; администратор добавляет учётные записи по мере необходимости через Supabase Authentication → Users (без заранее созданных User 1…7).
- SQLite schema 3, без потери существующих данных.

## Важно про изображения

Текущий `social_articles_*.csv` не содержит изображения. Поэтому старые runs не получат фото задним числом. Отдельный Dashboard Exporter 0.2.5 делает best-effort чтение `og:image` / `twitter:image` только для итоговых материалов и только в отдельном dashboard workflow. Ошибка получения картинки никогда не ломает bundle и не вмешивается в основной мониторинг.


Встроенную отправку приглашения из desktop в 0.5.1 намеренно не включаем: для email-invite нужен корректный password/deep-link onboarding. До его отдельного укрепления создание учётки остаётся административной операцией Supabase.
